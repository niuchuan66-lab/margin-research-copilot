## 二、分镜脚本

> 旁白为可直接照读的口播稿；操作与旁白同步进行。总时长 7:40。

### 镜头 0 · 开场（0:00–0:25）

**画面**：书架页，39 篇论文列表缓慢向下滚动，随后回到顶部。

**旁白**：

> 大家好，我是 niuchuanbo，这是我的参赛作品 Margin 科研助手。
> 它面向科研阅读与写作的全流程，覆盖 PDF 解析、抗幻觉问答、双语阅读、论文发现、引用图谱和写作辅助。
> 和常见的「把 PDF 丢给大模型总结」不同，Margin 把页码和版面坐标作为整条链路的主线，让每一句回答都能回到原文的那一行。

### 镜头 1 · 模块一：解析、OCR、去重、长文档（0:25–1:35）

**画面**：

1. 书架顶部展示批量导入结果与状态；
2. 打开扫描件论文详情，展示 955 个文本块与 bbox；
3. 上传 `1706.03762v7.pdf`（v1 已在库），解析完成后弹出语义去重提示（相似度 0.7174，建议「覆盖/保留两者/稍后处理」）；
4. 回到书架，指出 541 页 UDL 的状态为已就绪。

**旁白**：

> 先看解析。系统逐页读取 PDF：有文本层的页面直接提取字符坐标，没有文本层的页面才进入 OCR，所以 541 页的 UDL 只对 4 页做识别，15 页纯扫描件才会整篇识别。
> 每个文本块都带页码、字符框并集得到的 bbox 和章节路径，扫描件还会把像素坐标换算回 PDF 坐标，所以高亮不会错位。
> 重复上传同一个论文的新版本时，系统按正文 5-gram 计算相似度，v1 和 v7 是 0.7174，并给出覆盖或保留的建议，不靠文件名判断。
> 长文档解析走后台任务并限制并发，接口立即返回，前端轮询进度，不会把请求卡死。

### 镜头 2 · 模块二：抗幻觉问答与多篇对比（1:35–2:55）

**画面**：

1. 问答页选择 `1706.03762v1`，提问「β1、β2、ε 分别是多少」；
2. 回答出现后，逐个点击引用 chip，右侧 PDF 跳页并高亮对应句子；
3. 新提问：「GPT-1、GPT-3、BERT、Transformer 的模型规模分别是多少」，展示引用覆盖多篇；
4. 追问一个原文没有的字段，展示「库中未找到足够依据」。

**旁白**：

> 问答不是只给一段总结。系统先用 BM25 和关键词重叠做混合检索，命中块前后各扩一块，再按论文分别召回；多篇提问时交错合并，避免一篇论文占满上下文。
> 提示词强制每个事实句带编号引用，并区分「原文声明」和「模型归纳」。回答之后还有一步校验：引用的原句必须真的出现在检索文本里，回答里的编号也必须能对应到校验后的引用。
> 所以点击编号可以跳到对应页并高亮 bbox；原文没有给出的信息，系统会明确说库中未找到依据，而不是编造数字。

### 镜头 3 · 模块三：双语阅读与版本差异（2:55–4:15）

**画面**：

1. 阅读器左侧 PDF、右侧双语面板；点击「翻译本页」，右侧按页分组出现译文；
2. 滚动右侧分组，左侧 PDF 自动翻到对应页；
3. 点击正文中的 `[n]`，参考文献面板滚动并高亮条目，再跳到 PDF 页；
4. 鼠标停留在未翻译段落 500ms，出现悬停译文浮层；再次悬停同一段，提示来自缓存；
5. 翻到第 8 页，展示表格、公式、图注的着色标签；
6. 打开「版本差异」，切换旧版本，展示 25 改写 / 14 新增 / 8 删除与 LLM 修订总结，点击一条差异跳页。

**旁白**：

> 阅读页是 PDF 加双语双栏。整页翻译保留 block id 和 bbox，右侧按页累积；滚动右侧会反向驱动 PDF 翻页，滚动和翻页不会互相打架。
> 正文里的编号是按钮，点一下就能定位参考文献并跳回原文。未翻译的段落悬停半秒就出译文，结果按文本哈希缓存，同一段不会重复请求。
> 解析阶段还会识别表格、公式和图注：表格按列间隙和行对齐合并，公式按符号密度判断，图注按题注模式识别，右侧用不同颜色标记。
> 版本差异是段落级对齐：新增、改写、删除三组，每条都带双方页码；修订总结由模型生成，但页码标签会经过服务端校验，不合法就回退到确定性统计。

### 镜头 4 · 模块四：发现与推荐（4:15–4:55）

**画面**：

1. 发现页搜索「flash attention」，来源选 arXiv，结果列出标题、年份、作者；
2. 切换 OpenAlex 再搜一次；
3. 点击「按书架推荐」，展示推荐理由与「含 GitHub 复现代码」标记；
4. 点击一篇结果的「下载并入库」，提示已加入书架。

**旁白**：

> 发现页接入了 arXiv 和 OpenAlex，能按关键词检索标题、作者、年份和摘要，并从摘要里提取 GitHub 链接。
> 推荐会从书架标题抽取高频关键词，过滤已入库的论文，带开源复现代码的论文排在前面，并给出推荐理由。选中的论文可以直接下载入库，进入同一套解析流程。

### 镜头 5 · 模块五：引用图谱、综述与未来方向（4:55–5:45）

**画面**：

1. 图谱页点击「构建图谱」，展示 361 节点 / 803 条边的网络；
2. 右侧基石节点列表，说明 PageRank；
3. 点击「生成综述草稿」，展示带论文标题标注的段落；
4. 点击「提取未来方向」，展示 10 条方向与年份。

**旁白**：

> 图谱从每篇论文的参考文献出发，按 DOI、标题精确匹配、标题包含逐级匹配库内论文；只被一篇论文引用的外部文献会被剪枝，避免节点爆炸。
> 中心度优先用 NetworkX 的 PageRank，环境缺 SciPy 时回退到纯 Python 实现。当前 39 篇论文得到 361 个节点、803 条边，计算大约 3 秒。
> 综述只依据图谱节点、引用边和摘要生成，每个论断用论文标题标注来源；未来方向从各论文的 Future Work 段落抽取证据，按相似度合并重复方向，再按年份排序。

### 镜头 6 · 模块六：写作与可视化（5:45–6:30）

**画面**：

1. 写作页输入研究想法，点击「生成大纲」，展示 7 节结构与每节引用的文献；
2. 打开图脚本，选择 Mermaid，生成一张方法流程图；
3. 上传 `metrics.csv`，切换雷达图，生成图表与 LLM 图注。

**旁白**：

> 写作模块把研究想法和库内论文的标题、摘要一起交给模型，要求输出严格 JSON：标题、六到八节、每节引用的文献编号；解析失败或章节不足就回退模板。
> References 只来自库内论文和已解析的参考文献，不编造。图脚本支持 Mermaid、Graphviz 和 TikZ；CSV 可以出折线、柱状和雷达图，图注由模型根据前 10 行数据生成，只描述可见趋势，不宣称显著性。

### 镜头 7 · 增强：Agent 工具调用与 Python 沙箱（6:30–7:25）

**画面**：

1. 问答页切到「Agent 模式」，输入「下载 arXiv 1706.03762 并解析入库」；
2. 过程面板依次出现 `plan`、`arxiv.download`、`tool_result`，完成后给出「去书架查看」；
3. 再输入「用这组数算均值和标准差：12, 15, 18, 21」，展示 `python.exec` 的真实 stdout；
4. 输入一段包含 `open()` 的代码，展示被沙箱拒绝。

**旁白**：

> 最后是 Agent 模式。常见请求由规则直接路由，未命中的才交给规划模型生成最多三步的严格 JSON 计划，工具名必须在注册表里。
> 比如下载 arXiv 论文，会依次执行下载、入库和后台解析，前端实时显示每一步的工具名、参数和结果摘要。
> 需要计算时调用 Python 工具，但模型生成的代码不会进入 API 进程：只允许数学、统计、CSV、JSON 等白名单模块，禁止 open、eval、exec 和下划线属性，并在独立子进程里执行，8 秒超时、8KB 输出截断。包含危险调用的代码会直接被拒绝。

### 镜头 8 · 收尾（7:25–7:40）

**画面**：切到 README 架构图，再切到在线演示地址与仓库地址。

**旁白**：

> Margin 用单容器部署，默认 SQLite 和进程内检索，没有外部服务也能启动；缺少模型、OCR 或重型组件时会逐级降级。
> 项目采用 Apache-2.0，代码、文档和在线演示都可以在页面上找到。谢谢观看。

## 四、剪辑与导出

1. **粗剪**：按镜头顺序拼接，删除准备动作、误操作和超过 8 秒的等待；
2. **加速**：解析、整页翻译、图谱构建可用 2–4 倍速，画面角落标注「已加速」；
3. **字幕**：把本文旁白导入剪映/PR 自动识别，校对专有名词（bbox、PageRank、RapidOCR、arXiv）；
4. **画面标注**：在引用跳转、悬停翻译、表格着色、沙箱拒绝处加 1–2 秒圈注或箭头；
5. **导出**：H.264，1920×1080，30fps，码率 8–12 Mbps，AAC 192kbps，文件名 `Margin科研助手-演示视频.mp4`；
6. **自检**：完整播放一遍，确认无 Key、无个人信息、无报错弹窗、总时长在 5–8 分钟内。
